# Design Partner runtime threat model

## Assets and objective

Protected assets are the Docker host, NoPager containers, enrolled target, credentials, approval authority, audit history, and service availability. The key objective is that compromise of AI reasoning or the ordinary worker does not automatically grant unrestricted Docker-host control.

## Threats and controls

| Threat actor/failure                | Plausible attack                                               | Controls                                                                                                                                 | Residual risk / response                                                                                                             |
| ----------------------------------- | -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Compromised model/provider response | Prompt injection, invented command, repeated restart           | Structured validated output; only advertised typed actions; deterministic policy; Safe Mode; persisted action; helper ignores model text | Bad reasoning may cause a permitted restart after approval. Review evidence; use Kill Switch.                                        |
| Compromised web/control plane       | Forge approval/action or steal stored data                     | Authentication, origin checks, encrypted integration secrets, worker/helper independent gates, exact enrollment                          | It still cannot speak Docker API. Stolen helper credentials also require allowed local UID/socket access. Rotate and rebuild.        |
| Compromised worker                  | Try arbitrary Docker API, shell, substitution, replay          | No Docker socket/CLI/group; narrow protocol; peer UID + token; exact target; durable dedupe; control-plane/Compose blocks                | It can request the one allowed restart when all controls permit and can read its process evidence/secrets. Revoke token/stop helper. |
| Compromised runtime helper          | Invoke arbitrary Docker operations or tamper journal           | Small auditable code; fixed commands; hardened systemd unit; minimal files/network; dedicated account                                    | Docker-group authority is generally host-root equivalent. Treat as host compromise and rebuild.                                      |
| Stolen helper IPC credential        | Authenticate illicit requests                                  | Token permissions; separate random token; socket permissions; `SO_PEERCRED`; exact action/target                                         | Token plus execution as allowed UID can request the enrolled restart. Stop helper, rotate token, inspect journal.                    |
| Malicious/compromised target        | Masquerade as healthy, exploit daemon/kernel, replace identity | Immutable ID/name/project; external HTTP plus state verification; no target-supplied policy; isolation                                   | Container escape or convincing false health remains possible. Use disposable/staging defense in depth.                               |
| Docker daemon compromise            | Ignore identity/isolation or control host                      | No in-product control can make a compromised daemon trustworthy                                                                          | Host compromise. Isolate, revoke, rebuild from known-good media.                                                                     |
| Network failure/provider outage     | Detection noise, model timeout, HTTP verification failure      | Three-failure trigger, bounded provider call, consecutive recovery, fail closed/escalate, no blind retry                                 | Delayed response and availability loss require human investigation.                                                                  |
| Local IPC loss/timeout              | Lost restart response produces uncertain state                 | Helper journal + action UUID; ambiguous classification; max one attempt; duplicate rejection                                             | Operator must establish actual state. Automated retry is forbidden.                                                                  |
| Target replacement/race             | Reuse name for attacker container                              | Immutable 64-hex enrollment and fresh pre/post inspect                                                                                   | Explicit re-enrollment is required; daemon compromise remains out of scope.                                                          |

## Assumptions and out of scope

Linux root and Docker administrators are trusted; filesystem permissions and `SO_PEERCRED` work; PostgreSQL is durable; the health URL checks meaningful behavior; the target is outside NoPager's Compose project; and the Alpha host is disposable/staging.

Protection against a compromised kernel/Docker daemon/helper, hostile multi-tenant local users, arbitrary production actions, and proof that HTTP 2xx means the entire application is correct are not provided.
